HIVE DEMO — COMMANDS
===========================

Environment: Apache Hive 4.0.0 in Docker Desktop on macOS.
Run SHELL commands in the Mac Terminal.
Run SQL commands at the Beeline prompt.

------------------------------------------------------------
A. DOCKER SETUP (MAC TERMINAL)
------------------------------------------------------------

# Start Docker Desktop
open -a Docker

# Download the Hive image (only needed once)
docker pull apache/hive:4.0.0

# Create the HiveServer2 container (only the first time)
docker run -d \
  --name myhive \
  -p 10010:10000 \
  -e SERVICE_NAME=hiveserver2 \
  apache/hive:4.0.0

# If the container already exists, start it instead:
docker start myhive

# Check container status and logs
docker ps
docker logs -f myhive

# Copy Twitter.txt from the repository directory on the Mac
docker cp Twitter.txt myhive:/tmp/Twitter.txt

# Verify the copied file
docker exec -it myhive ls -lh /tmp/Twitter.txt

------------------------------------------------------------
B. CONNECT TO HIVE (MAC TERMINAL)
------------------------------------------------------------

docker exec -it myhive beeline -u "jdbc:hive2://localhost:10000/default"

Important: Your port mapping is 10010:10000. Since Beeline is running inside the container, it connects to port 10000. If you run Beeline directly on your Mac, you would use port 10010.

All SQL statements below are entered at the Beeline prompt.
The dataset file must have been copied to /tmp/Twitter.txt first.

------------------------------------------------------------
D. TWITTER TABLE
------------------------------------------------------------

CREATE TABLE IF NOT EXISTS Twitter (
    `date` DATE,
    date_time TIMESTAMP,
    tweet_text STRING,
    type STRING,
    media_type STRING,
    hashtags STRING,
    tweet_url STRING,
    retweets INT
)
ROW FORMAT DELIMITED
FIELDS TERMINATED BY '\t'
LINES TERMINATED BY '\n'
STORED AS TEXTFILE;

-- Load the local file from inside the container.
-- Beeline is running inside the container, so this path is the container path /tmp/Twitter.txt.
LOAD DATA LOCAL INPATH '/tmp/Twitter.txt'
INTO TABLE Twitter;

-- Inspect the table and a few rows.
DESCRIBE Twitter;

SELECT * FROM Twitter LIMIT 5;

SELECT COUNT(*) FROM Twitter;

------------------------------------------------------------
E. BASIC QUERIES
------------------------------------------------------------

-- Display three tweets whose type is text.
SELECT tweet_text, type
FROM Twitter
WHERE type = 'text'
LIMIT 3;

-- Display the ten tweets with the highest retweet counts.
SELECT retweets, tweet_text
FROM Twitter
ORDER BY retweets DESC
LIMIT 10;

-- Display non-empty hashtags ordered by date and time.
SELECT date_time, hashtags
FROM Twitter
WHERE hashtags IS NOT NULL AND hashtags != ''
ORDER BY date_time;

-- Count tweets per date and type when media_type is not empty.
SELECT `date`, type, COUNT(*)
FROM Twitter
WHERE media_type IS NOT NULL AND media_type != ''
GROUP BY `date`, type
ORDER BY `date` DESC;

-- Find the maximum retweets per date for photo tweets, keeping dates whose maximum is greater than 10,000.
SELECT `date`, MAX(retweets) AS mt
FROM Twitter
WHERE media_type = 'photo'
GROUP BY `date`
HAVING MAX(retweets) > 10000
ORDER BY mt;

------------------------------------------------------------
F. PARTITIONED AND BUCKETED TABLE
------------------------------------------------------------

-- PARTITIONED TABLE examples

CREATE TABLE IF NOT EXISTS TwitterMod (
    `date` DATE,
    date_time TIMESTAMP,
    tweet_text STRING,
    media_type STRING,
    hashtags STRING,
    tweet_url STRING,
    retweets INT
)
PARTITIONED BY (type STRING)
CLUSTERED BY (`date`) INTO 3 BUCKETS
ROW FORMAT DELIMITED
FIELDS TERMINATED BY '\t'
LINES TERMINATED BY '\n'
STORED AS TEXTFILE;

-- Insert text tweets into the text partition.
INSERT INTO TABLE TwitterMod PARTITION (type='text')
SELECT `date`, date_time, tweet_text, media_type,
       hashtags, tweet_url, retweets
FROM Twitter
WHERE type = 'text';

-- Insert link tweets into the link partition.
INSERT INTO TABLE TwitterMod PARTITION (type='link')
SELECT `date`, date_time, tweet_text, media_type,
       hashtags, tweet_url, retweets
FROM Twitter
WHERE type = 'link';

-- Insert video tweets into the video partition.
INSERT INTO TABLE TwitterMod PARTITION (type='video')
SELECT `date`, date_time, tweet_text, media_type,
       hashtags, tweet_url, retweets
FROM Twitter
WHERE type = 'video';

-- Inspect partitions.
SHOW PARTITIONS TwitterMod;

-- Compare the counts for the text partition.
SELECT COUNT(*)
FROM Twitter
WHERE type = 'text';

SELECT COUNT(*)
FROM TwitterMod
WHERE type = 'text';

-- Inspect table metadata.
DESCRIBE FORMATTED TwitterMod;

------------------------------------------------------------
G. BUCKETING CHECK
------------------------------------------------------------

SET hive.enforce.bucketing = true;

-- Sample one of the three buckets.
SELECT COUNT(`date`)
FROM TwitterMod
TABLESAMPLE(BUCKET 1 OUT OF 3 ON `date`);

-- Compare with the source table count.
SELECT COUNT(`date`)
FROM Twitter;

NOTE:
Bucketing is a physical data-layout feature. The table must be
populated using an execution path that writes bucketed files.
Check the table metadata and files if the sampling result is
unexpected. Hive version and execution configuration can affect
the behavior of older classroom examples.

------------------------------------------------------------
H. EXIT AND RESTART
------------------------------------------------------------

-- At the Beeline prompt, exit Hive:
!quit

# Back in the Mac Terminal, stop the container:
docker stop myhive

# On a later day, start the existing container:
open -a Docker
docker start myhive

# Reconnect:
docker exec -it myhive beeline -u "jdbc:hive2://localhost:10000/default"

IMPORTANT:
- The Docker image apache/hive:4.0.0 is reusable.
- The container myhive is created once and can be stopped/started.
- Do not run `docker run --name myhive ...` again if myhive exists.
- Stopping a container preserves its writable filesystem.
- Removing the container can delete data stored only inside it.
